Аналитика качества ПО: Как превратить логи тестов в метрики
Введение

В крупных программных комплексах количество автоматизированных тестов исчисляется тысячами. В таких условиях стандартного бинарного статуса «прошел/не прошел» (Passed/Failed) становится недостаточно для глубокого понимания состояния продукта.

QA-Metrics-Toolkit — это специализированная библиотека на Python, разработанная для трансформации сырых артефактов тестирования в наглядные метрики качества (Quality Gates). Проект демонстрирует полный цикл разработки: от написания кода до публикации пакета на TestPyPI.
Концепция и логика работы

Основная задача библиотеки — агрегация данных из отчетов формата JUnit XML, который является стандартом для большинства современных фреймворков (pytest, JUnit, TestNG).
1. Анализ стабильности (Stability Index)

Библиотека автоматически вычисляет коэффициент успешности прохождения тестовой сюиты по формуле:
S=Ttotal​Tpass​​×100%

Где:

    Tpass​ — количество успешно пройденных тестов;

    Ttotal​ — общее количество запущенных тестов.

Это позволяет команде отслеживать регрессию не по факту падения одного теста, а по динамике изменения процента успешности.
2. Временной профиль (Performance Profiling)

Библиотека анализирует атрибут time в XML-отчетах, выявляя самые «тяжелые» тесты. Это критически важно для оптимизации CI/CD пайплайнов, так как позволяет точечно сокращать время сборки проекта.
Автоматизация разработки (Makefile)

Принцип By-design not by-mistake реализован через строгую автоматизацию всех этапов жизни проекта с помощью Makefile. Использование виртуального окружения гарантирует, что разработка ведется в изолированной среде.
Основные таргеты:

    Линтинг (make lint): Использование ruff для обеспечения чистоты кода и соблюдения стандартов PEP 8.

    Типизация (make types): Статическая проверка типов с помощью mypy для предотвращения ошибок времени выполнения.

    Тестирование (make test): Запуск pytest для проверки корректности работы самих алгоритмов парсинга.

    Сборка (make build): Автоматизированная упаковка проекта в дистрибутивы .tar.gz и .whl с использованием модуля build.
